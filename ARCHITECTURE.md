# Architecture note (Milestone 1 portfolio prototype)

## Components and boundaries
```
Extension side panel (MV3)  --HTTP+WS, 127.0.0.1:4200-->  Backend (coordinator)
   memory-only UI state                                     |-- Policy engine (URL/route/read-only/auth)
   secret pasted by operator                                |-- Model adapter (fake | anthropic | openai-stub)
                                                            |-- Playwright bridge --CDP, 127.0.0.1:9333--> dedicated Chromium
                                                            `-- Audit store (metadata only, in memory)
Synthetic site 127.0.0.1:4100 (SYN-#### records, fixtures, mutation counter)
```
- **Extension <-> backend.** The backend generates a random session secret at startup and prints it once to the operator's terminal. The operator pastes it in the panel (kept in JS memory only). Every HTTP call needs `x-demo-session`; mutating calls also need `Content-Type: application/json`. A request **must carry** an Origin equal to `chrome-extension://<id>` (id derived from the manifest `key`); a missing Origin is rejected (the secret alone is not enough, fixed after review), Host must be loopback (anti DNS-rebinding), preflights are granted to that origin only, WebSocket upgrades check Origin and then require an auth frame. Errors are generic (`{"error":"CODE"}`). Everything binds to 127.0.0.1.
- **Local prototype vs production.** The prototype is the operator's own machine/VPS driving a dedicated Chromium over a loopback CDP endpoint. It is **not** a cloud backend remotely controlling a user's browser. A production design needs a different browser-control and trust model (isolated, ephemeral, network-fenced browser workers; client-controlled secrets store; persistence, auth and audit in the client's environment). None of that is built here.
- **Browser.** Playwright's bundled Chromium, fresh `mktemp` profile that the launcher removes on every shutdown path (SIGINT/SIGTERM/browser closed) through one awaited cleanup (a hard kill of the launcher itself, or a crash, can still leave the directory behind). The launcher refuses a CDP port that is already in use and proves the responder is its own child via a per-launch nonce read back through `Browser.getBrowserCommandLine`. The backend **refuses to attach** unless the browser's real command line matches the launch it was handed: the per-launch nonce and exact profile directory (passed from `npm run browser` through a 0600 handoff file in the temp dir, deleted on close), the exact proxy bypass list `<-loopback>;127.0.0.1:<site>;127.0.0.1:<backend>`, loopback debugging address, dead proxy, host-resolver rules, WebRTC policy and every background-network flag. (Same-user processes can still read the handoff file and the CDP port; see Known limitations.) `--enable-automation` is set because that CDP command requires it (Chrome shows its automation infobar). The bridge controls only one tab it creates, inside a **fresh isolated (non-persistent) browser context per task** with downloads and service workers disabled. The default context (extension, about:blank) is never driven by the agent.

## Model routing
Provider interface (`providers/types.ts`): `complete(system, messages, tools) -> tool calls + usage`. `resolveProvider` rejects unknown provider / unapproved `provider:model` / missing key **before any client is constructed**, so no network call can occur; a metadata-only rejection event is audited. Endpoints are code constants (no user-supplied endpoints). The Anthropic adapter uses `@anthropic-ai/sdk` tool use with SDK retries off (the coordinator owns bounded retries) and informational platform headers blanked (the SDK has no telemetry channel). Tool-result text is marked untrusted. The **OpenAI adapter is a stub that fails safely, so Milestone 2's "both providers by configuration" requirement is NOT met.** The deterministic fake provider powers the tests and offline demo and is always labelled FAKE.

## Constrained tools
`navigate`, `inspect`, `lookup_record`, `open_record`, `finish` only, each with a strict zod schema (unknown keys rejected). No JS eval, selectors, click/type, or raw Playwright. `open_record` takes an opaque link id resolved server-side. `source_url` and `retrieved_at` are set by the coordinator from the browser's URL and clock; `finish` has no such fields. The coordinator re-validates `finish` against extracted evidence: wrong values -> `uncertain`; conflicting source values -> `uncertain` (never picks a side); `not_found` is accepted only after a completed search with zero exact matches. Reported values are the evidence values.

## Enforcement points (all below the model)
1. Tool-argument validation (before any browser action).
2. URL policy pre-check on every navigation-like tool: exact scheme/host/port, no userinfo, no deceptive hosts, malformed rejected; approved read routes only; route-semantic write detection (a GET to `/delete` is a write, a POST anywhere is a write).
3. `context.route('**/*')` for **every** request (navigations, subresources, form posts, fetch): allowed requests are fetched with `maxRedirects: 0`. Playwright does not re-run the route handler for redirect hops after the first, so **Chromium is never allowed to follow a redirect**: the handler policy-checks the `Location` target, aborts the request, and `goto()` re-issues the target as a brand-new navigation that comes back through the handler. Every hop is therefore classified before it is requested; a hop cap (5) blocks loops. (Earlier versions only checked the first hop; a chain allowed -> allowed -> `/delete` mutated the site. Found by external review, now covered by a test.) Redirects on subresources are aborted.
4. `context.routeWebSocket` closes every page WebSocket (the site needs none) without connecting.
5. Popups are closed immediately and audited; any block ends the task as `blocked` (fail closed).
6. Auth boundary: before any extraction the URL and **every frame** are checked for credential/OTP fields (boolean only); then a single evaluation returns `{href, auth, data}` so a timer cannot slip between check and read; the URL and all frames are re-checked after extraction and data is dropped on any difference. **All page reads run in a CDP isolated world** (`Page.createIsolatedWorld`) with pristine DOM/builtins, so a page that overrides `document.querySelector` / `Element.prototype.*` in its own world cannot hide a credential form (this was a confirmed bypass of the earlier main-world `evaluate`). Extraction is constrained to explicit elements/attributes: `[data-field]` elements whose name is on a fixed allow-list and whose element chain is visibly rendered; **text is collected node by node**, skipping any descendant that is `display:none`, `visibility:hidden`, `opacity:0`, `hidden`, `aria-hidden=true` or has no box (hidden descendants of a visible field are skipped; non-rendered text nodes such as closed `<details>` bodies are NOT detected). Credential detection descends into open shadow roots and additionally scans CDP's pierced DOM (which exposes closed shadow roots and iframes). `data-source` is restricted to letters/spaces; hard caps on element count, per-field length and aggregate bytes live **inside the page script**; whitespace is normalised and a lossy cut (value over the cap, collection stopped by the cap, over-long source/link, element or byte limits) sets `truncated`, which can never verify as success. **Not detected:** visual hiding that keeps a box and non-zero opacity (same-colour text, `font-size:0`, off-screen/clipped positioning, `clip-path`, CSS-generated content is not read); see Known limitations. Result: `human_action_required`; resume is out of scope.
7. Browser-level containment in `launch.ts`: dead proxy `127.0.0.1:9` with `--proxy-bypass-list=<-loopback>;127.0.0.1:<site>;127.0.0.1:<backend>` (`<-loopback>` removes Chrome's implicit loopback bypass), `--host-resolver-rules="MAP * ~NOTFOUND, EXCLUDE 127.0.0.1"`, `--dns-prefetch-disable`, WebRTC non-proxied-UDP disabled, background networking/sync/component update/pings/domain reliability off.
8. Budgets and cancellation: one task-wide `AbortSignal`, aborted by Stop or by a wall-time timer. It is raced against every provider call and backoff, passed to the provider, and **closes the task browser context** (cancelling in-flight navigation); the coordinator re-checks Stop/deadline after every awaited operation (provider, navigation, auth check, extraction). Stop is claimed with `runner.begin()` BEFORE the CDP connect, so an early Stop is not lost; browser-context creation is raced against the signal (a late-resolving context is closed); `active` turns false only after browser cleanup completes (the abort-triggered context close is awaited too, and stale route handlers of a closed task touch no shared state); `closeTaskTab` captures and clears its own handles synchronously so a slow close cannot clear a newer task. Remaining gaps: the connect phase is not bounded by the wall-time budget; an already-dispatched CDP command is not cancelled mid-flight (it is abandoned and its context closed), and the shared bridge relies on the single-task `active` serialisation rather than per-task handle objects. Also bounded: steps, model calls, retries (bounded backoff), extracted size (counted at the real extracted size).
9. Provider transport: the Anthropic client's fetch is wrapped with `redirect: "manual"` and any 3xx is refused (a 307/308 would re-POST task + page content to another host); SDK logging is explicitly `off` (ANTHROPIC_LOG is ignored).
10. Task input: record identifiers must be exact (`SYN-####` standing alone; exactly one per task); malformed, glued or multiple ids are rejected before any browser work.

## Transient data flow
Page text -> in-process memory -> (tool result) model provider -> coordinator verifies -> result card in panel. Not written to disk, browser storage or the audit store, and the application logger and the SDK emit no content. Test and script output is kept content-free (assertions print labels/IDs only, no result dumps) and `scripts/run-tests.ts` scans captured vitest stdout/stderr plus `test-output/` for leak markers on both passing and failing runs, printing only marker IDs. That is a scan of what the test run captured, not a proof about every possible log path (e.g. a developer enabling debug logging elsewhere). Audit events hold only task_id, action_id, category, outcome, safe code (closed vocabulary; free text is coerced to `UNKNOWN_CODE`), timestamp, duration. The source URL is in the displayed result only. Progress messages are templated and content-free.

## Production gaps (honest list)
- **Chrome profile artifacts.** A disposable profile and a non-persistent context are used and a scan of the profile after the test run found no markers (`PROFILE-RESIDUE: 0`), but that is one measurement, not proof of "no local copy" (swap/page files, GPU/crash artifacts, OS caches are not inspected). Production needs ephemeral, encrypted, destroy-on-completion workers.
- **Background/uncontained traffic.** App-level interception cannot see browser-internal traffic. Before the proxy flags, sampled sockets showed Chromium contacting Google endpoints (:443 and :5228) during an idle window; with the flags the same sampling saw none. Flag-based containment is best effort and depends on Chrome behaviour: the extension service worker and Chrome-internal fetches share the same flags but are not individually interceptable. The production answer is an OS/network-level egress firewall (default-deny, allow-listed destinations), not browser flags.
- `<link rel=preconnect>` did not produce a connection in our run even without the flags (so that vector was not demonstrated red); UDP/STUN from WebRTC did (8 datagrams) and is now contained.
- Loopback CDP is a powerful local capability; any local process running as the same user can reach it.
- Anthropic SDK/endpoint use needs the client's secrets store and healthcare agreements; no BAA is implied. Audit store is in-memory; no persistence, crash recovery, write approvals, downloads, vision, resume, mid-task redirect.
- The panel is a standard MV3 side-panel page; the demo script opens it in a tab because Chrome offers no automation hook to open the native side-panel UI.
- Controlled-site read-only semantics (route allowlist) do **not** make arbitrary third-party portals read-only; site-specific adapters and a network boundary are future work.
- Only the Anthropic adapter is real; the OpenAI adapter is a stub.

## Known limitations (not fully closed)
- Visibility is a heuristic over computed style/boxes. Text that keeps a box and opacity but is visually hidden (same colour as background, `font-size:0`, clipped or positioned off-screen) is still read; CSS-generated text and input values are not read.
- A same-user local process can read the launcher handoff file (nonce) and talk to the loopback CDP port; the nonce binds acceptance to the launch, it is not a defence against a hostile local user.
- In-flight CDP commands are abandoned rather than cancelled; the browser context is closed to stop the work.
- The shared bridge is serialised by the `active` flag, not by per-task handle objects.
- Browser egress containment is flag-based and best effort (see above); production needs OS-level egress control.
- Non-rendered text nodes (closed `<details>` bodies, unslotted text under declarative shadow DOM) can still be read, since visibility is a heuristic.
- The per-launch nonce is visible to ANY local user via /proc/<pid>/cmdline (not only the same user); it binds acceptance to a launch, it is not a secret.
- UNMET build-sheet item: the manual browser-launch fallback is not provided; the launcher is the only supported path.
- The connect phase is not bounded by the wall-time budget.
- The launcher cannot clean up its profile directory if it is itself SIGKILLed.
